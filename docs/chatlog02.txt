● The interface work is in place: LOTUS can now be driven headless or windowed,
  and both drive the same sessions with the same MCP tools. I've left everything
  uncommitted (see the last section).

  How to run it
  - Headless: lotus-mcp host.json, for an agent alone.
  - Windowed: lotus-desktop host.json.
  - Windowed with MCP: lotus-desktop --mcp host.json. The agent launches the
    window as its MCP server and you watch and use the same sessions. The
    sidebar footer shows whether MCP is attached, the toolbar shows who last
    acted ("you" or "agent"), and lotus_focus_session lets an agent switch your
    view to a session.

  Sessions
  - Primary: mounts a named card at <storage>/cards/<name>/, with real SD/NAND
    reads and writes that persist. Only one primary per card can run at a time.
  - Secondary: gets a scratch folder that is empty or a copy of a card, taken
    while the primary may still be running. It's deleted when the session stops.
    After a crash, only its logs are kept.
  - Running several at once: each session has its own lock, so a long run on one
    never blocks another, and starting or stopping one doesn't wait on the
    others. Every session is addressed by its ID over MCP.
  - Limit: the default is 4 sessions, which is the load that has been tested.
    You can raise it to 16 with max_sessions in the host config.
  - Patch builds: a new asset_directories host-config field approves every .3dsx
    in a folder. Rebuilt patch variants show up without restarting LOTUS.
  - Naming: I called the persistent storage a "card" instead of "profile". Your
    uncommitted Wave-3 glossary already uses Profile for session settings (T24).

  Interface
  - The collapsible sidebar is the main navigation (Ctrl+B). Primaries are
    top-level entries, secondaries are nested under the card they copied, and a
    secondary with no parent card is top-level. When collapsed it becomes a
    strip of status icons.
  - The toolbar has Run/Pause, Step, Reset, Load (approved content or Open
    file…), Stop, zoom (Fit/1×/2×) and screen layout.
  - The gauges show fps with a small history graph, speed against the 59.83 Hz
    target, frame count, audio, worker memory, and who is in control.
  - The inspector (Ctrl+I) shows registers while a session is paused.
  - Colours follow vercel.md: dark neutrals, with colour only for state.

  Testing
  - On both AZAHAR and CITnLO, all the real-worker tests pass. That includes
    four sessions started at once, crash isolation, a card surviving a stop, and
    secondaries being deleted. Workspace tests, clippy with warnings denied,
    fmt and smoke.ps1 also pass.
  - Existing MCP clients still work unchanged.
  - New script tests/test_windowed_mcp.py has an MCP client drive the windowed
